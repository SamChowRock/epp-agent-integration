name: schedule-practice
description: 当用户希望定时或在指定时段随机收到 EPP 练习，或需要恢复、调整这类练习任务时使用。
---

在同一个 Codex 对话中随机提醒练习。时间判断由本目录脚本负责；实际练习读取并复用 [practice-expressions](../practice-expressions/SKILL.md)。只使用用户已允许用于当前宿主的练习池；加入或退出练习池仍须用户明确指定。

## 配置与创建任务

1. 使用本目录的 [config.example.json](config.example.json)，或用户提供的同结构 JSON。示例为北京时间每天 10:00–21:00，随机 3 或 4 次；次数在两个整数间等概率选择，时段无重复抽取。窗口左闭右开，只支持同日窗口、整点或半点，最后候选时刻是 20:30。配置不含账号、令牌、服务 URL 或个人绝对路径。
2. 把本 Skill、脚本、配置和状态文件的**绝对路径**写入任务提示。默认状态为仓库 `.local/practice-schedule/state.json`；个人配置也可放在同一忽略目录。每个账号/服务/对话使用独立且稳定的状态路径；更换账号或服务后重新核对授权，不能用新路径重复启动同一任务。
3. 先在普通对话手动运行下述 `check`，并核对 EPP 练习工具、`practice:read / practice:write` 和获准材料范围。缺工具、服务、权限或材料范围时，只准备暂停的任务并说明具体缺口；不能用直接生成的题目冒充 EPP 练习。
4. 用户要求创建任务时，使用当前宿主的自动化工具，优先创建回到同一对话的 heartbeat。在配置时区的窗口内每半小时检查一次；时间窗口改变时同步调整触发时间。创建后把工具实际返回的 `automationId` 写入本任务提示，用于准确暂停同一个任务；已有任务先核对其身份，不猜 ID，也不暂停其他任务。不要改成独立 cron 任务绕过同一对话能力，也不要直接编辑宿主私有调度文件。此脚本本身不注册或常驻运行任务。

任务提示要求每轮先读取本文件，运行 `check` 并按下文处理；用户回答后复用 `practice-expressions` 保存原答案与评估。把实际配置、状态和 Skill 路径列入提示，模型与推理配置沿用宿主默认值。创建后报告真实状态和前置条件；本地脚本通过不代表后台插件调用或通知已通过。

## 每次定时唤醒

下面从仓库根目录展示命令；任务中替换为已确定的绝对路径，始终沿用同一个配置和状态文件。

```sh
node plugins/epp/skills/schedule-practice/scripts/random-slots.mjs check \
  --config plugins/epp/skills/schedule-practice/config.example.json \
  --state .local/practice-schedule/state.json
```

- 返回 `action: quiet`：结束本轮，不调用 EPP、不展示隐藏的当天计划、不发送例行“暂无练习”消息。
- 返回 `action: practice`：保留 `reminderId`，先用 `epp_get_practice` 查询 `{ "identity": { "kind": "current" } }`。已有待答题就展示保存的原题；已有 Agent 待生成或待评估阶段按练习 Skill 恢复；已有已评估结果但尚未自评时，展示已有反馈并等待用户明确自评。只有成功查询得到 `attempt: null` 时，才使用本次 `reminderId` 作为 `epp_start_practice` 的 `clientOperationId` 开始一道新题；查询报错不等于没有当前尝试。
- 沿用 EPP 返回的尝试和阶段身份，按完整 `generationRequest` 出题并保存，展示实际保存的题目。首次作答前保持隐藏目标、提示和参考不可见。用户自行作答和自评；用户没有回复时只保留/提醒原题，不累计新题。
- 本轮内容已保存且已在对话中展示后，用本次身份确认提醒：

```sh
node plugins/epp/skills/schedule-practice/scripts/random-slots.mjs ack \
  --config plugins/epp/skills/schedule-practice/config.example.json \
  --state .local/practice-schedule/state.json \
  --id <本次reminderId>
```

响应未知时先查原 `reminderId` 对应的 EPP 操作或原尝试；相同身份重放，不换身份重复开始。未成功读取/保存/展示时不 `ack`。恢复尝试和题目上传分别复用练习 Skill 的操作身份规则。

## 暂停与恢复

发现 EPP 练习工具不可用、服务不可达、所需权限失效或材料范围未获授权时，停止业务调用且不 `ack`，并通过宿主自动化工具将提示中绑定的 `automationId` 对应任务设为 `PAUSED`。先读取该任务的当前设置，保留名称、时间、目标对话、提示和其他设置，仅改变状态；保留原配置、日计划与业务操作身份。以工具返回的暂停结果为准，报告实际缺口及恢复条件：练习权限缺失与材料范围未授权分别说明。暂停失败、身份无法核实或缺少自动化工具时，明确说明“未能暂停，需要用户介入”，不能声称后续调度已停止。

单次业务写入响应未知时仍先按原身份查询，不把未知结果当作未保存；如果恢复查询也因上述前置条件缺失而无法执行，暂停当前任务。同一故障未变化时不反复通知。用户明确要求恢复后，先重新核对工具、服务、权限与材料范围并手动跑通，再启用原任务；条件自行恢复不自动激活。

## 时间与恢复边界

每天首次检查保存全天随机计划，后续读取同一计划。一次提醒只在对应半小时内有效；错过不补发，离线、暂停或服务失败时实际提醒可能少于配置次数。`ack` 保证后续检查不再领取该时段，不能证明操作系统通知已送达；本地文件与聊天消息之间没有原子提交。

当天配置绑定计划，改动后脚本会停止，恢复原配置或等下一自然日再启用新配置；同步更新自动任务的触发窗口。状态损坏或日期倒退时保留原文件并核对原因，不删除状态重抽。出现 `.lock` 错误时先确认所有本脚本进程已结束，再清理对应锁文件；不能清理仍在运行的锁。

脚本只需 Node.js 22 或更新版本，使用内置模块；不调用模型、EPP、数据库或通知 API。宿主仍需运行检查，默认示例每天最多 22 次后台唤醒，只有随机命中的 3 或 4 个时段继续练习；后台唤醒也可能消耗宿主用量。本地运行需要电脑、Codex 和 EPP 服务可用，授权到期仍通过宿主正常重新登录。
