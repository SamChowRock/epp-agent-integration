---
name: practice-expressions
description: 使用 EPP 插件练习已收录英语表达，处理练习池、出题换题、提示参考、原答案评估、表达归属、自评、历史和中断恢复。
---

通过当前连接的 EPP MCP 工具，一次练习一道题。只使用用户明确指定的正式表达身份和材料，不批量读取无关记录；没有身份时使用服务提供的 Web 星图地址让用户选择，不猜测身份或 localhost。记录新表达使用 record-expressions。

练习需要独立 `practice:read / practice:write` 权限；旧记录授权不会自动扩大，缺权限时让用户在目标 EPP 服务重新授权。账号密码和令牌由宿主认证机制保存，不放入工具参数。

1. **加入与开始。** 只有用户明确要求时，使用 `epp_set_practice_eligibility` 将指定表达加入或退出练习池。用 `epp_start_practice` 开始；用户明确换题时排除当前表达。为每次写入生成并保存稳定 `clientOperationId`，沿用返回的尝试、阶段生成身份和规则版本，不用聊天序号或 JSON-RPC ID 替代。
2. **自身 AI 出题。** 完整阅读服务返回的 `generationRequest`：规则、输入快照、版本、生成身份和输出 schema。由你当前的 AI 生成并通过 `epp_submit_practice_question` 上传题目或安全失败；此路径不调用 EPP 文本模型或 Sampling。生成者/模型身份只是客户端声明，未知值保留未知。题目保存成功后，向用户展示已保存的题目；不能提前泄露隐藏目标、提示或参考。
3. **辅助与原答案。** 用户请求提示或参考时，先调用 `epp_reveal_practice_assistance` 记录对应级别，成功后再展示返回内容。作答前额外解释会泄露目标或参考时，也须先记录对应辅助；辅助只能升级，不能事后降级。用户作答后用 `epp_submit_practice_answer` 逐字保存原始英语答案，不先纠错、不润色、不补写用户答案。仅对答案来源作客户端声明，不宣称 EPP 已证明是用户亲自输入；MCP 无法独立观察宿主展示，`none` 本身也不能证明独立作答。
4. **评估与证据。** 按已保存答案返回的完整 `generationRequest`，使用自身 AI 评估，再以绑定身份通过 `epp_submit_practice_evaluation` 上传或安全失败。`sourceSpan` 必须是原答案的逐字片段。表达自身 `expressionUse.usage` 独立于整句含义、自然度和综合结果：无关错误不能抹去正确用法；隐藏目标未使用不能被编成目标失败。展示已保存反馈，不把结构校验通过称为语言质量通过。
5. **替代表达归属。** 如结果返回归属生成要求，阅读服务提供的候选集合和完整规则，用自身 AI 核对，再通过 `epp_submit_practice_attribution` 提交集合内的精确候选身份或无法确认。不能自带用户、版本、未返回身份，不能自动收录未收录的表达；含混或失败不制造证据。结果反馈可先展示，无需等待归属；不得回退 EPP 模型。
6. **自评与历史。** `epp_set_practice_feeling` 只记录用户明确给出的这一次感受，不能根据模型判断代选“掌握了”。系统证据与用户感受分开展示。用户请求历史时，使用 `epp_get_practice_history` 按指定正式表达分页读取；新的练习仍一次一道题。
7. **恢复与失败。** 断线、响应未知、重启、重新授权或重连后，先用 `epp_get_practice` 按原尝试、原操作身份或当前尝试查询事实和未完成生成要求。查询不修改状态。相同身份同内容重放；未知结果先查询，不能换身份重复保存。`generationRequest.retryRequired: true` 表示原阶段已失败，须先用 `epp_retry_practice` 显式开启该阶段，再按返回的新生成身份生成和上传；归属失败时即使尝试已 evaluated，也遵守此标记。未标记或 false 的正常待生成要求直接继续。重试保留目标、原答案和首次提交边界；旧身份的迟到结果不能提交到新阶段。已成功结果不能覆盖；恢复不把 Agent 尝试切换成 EPP 模型。

报告实际已保存的题目、原答案、评估、辅助和证据状态。确定性校验与客户端声明不证明宿主语言质量、真实用户输入或没有额外提示；实际宿主验收以工具轨迹和对话为依据。
